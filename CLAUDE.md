## PROJECT CONTEXT (do not deviate)

You are helping a 4-person, 24-hour hackathon team build **NetCoop AI**: five agents exchange **validatable evidence** over a versioned protocol, challenge each other, and publish one defensible JSON diagnosis of a campus network fault. Data is synthetic (organizer Colab generator + our labeled scenarios). Never touch real network devices; remediation is simulated on fixture copies only.

Scoring: interoperability 30%, evidence/accuracy 25%, orchestration/conflict resolution 15%, robustness 15%, innovation/usability 10%, code/docs/demo 5%. **P0 core first; no UI/MCP/HITL work may break P0.**

### Components (exactly these — do not invent more agents)
| Component | Kind | Owns |
|---|---|---|
| Normalizer | service (NOT an agent) | generator adapter, field aliases, units, 5-min windows, counter deltas/resets, topology IDs, validation, provenance + quality flags |
| Orchestrator | service | agent-card registry, routing, validate-every-message bus, timeouts, retries, max 2 verification rounds, duplicate-ID drop, SQLite event log, correlation-failure fallback |
| Performance Agent | in-process | latency, jitter, loss, throughput vs capacity, utilization, congestion |
| Infrastructure Agent | in-process | device status, CPU/memory, queue drops, interface errors, link flaps, Wi-Fi RSSI/retries; emits supporting AND contradicting findings |
| Connectivity Agent | **separate REST process** (FastAPI) | topology, blast radius, common upstream dependency, DNS/DHCP, reachability; **consumes peer findings before its final output** |
| Correlation Agent | in-process | rank global signatures, weigh supports/contradicts, issue QUERY when disputed/stale/close, abstain, `heuristic-v1` confidence + decision gates |
| Reporting Agent | in-process | validate evidence/finding/affected IDs, serialize report-1.0 JSON + Markdown, explain actions using only cited findings |

Optional LLM: only for picking the next read-only check, comparing hypotheses, or explaining; output must be structured and is rejected if it cites nonexistent evidence. Everything must run with no API key. Keys come from `.env` only.

### Stack
Python 3.10+, Pydantic v2 (models are the **single source of truth**), FastAPI + uvicorn + httpx (Connectivity REST), jsonschema (validation at receive boundaries), SQLite (event log), pytest. CLI: `netcoop` (run / eval). Dashboard: React + Vite (P1), reads report/event API and exported schemas only. MCP (P2) is a read-only tool interface, NOT the agent protocol.

### Conventions (protocol, normalizer adapter, bus, event log and Connectivity REST service exist on `main`; agents, `agents/base.py` and `orchestrator/run.py` arrive in Phase 2 — build them to these conventions)
- Agents implement `handle(msg: Envelope, ctx: IncidentContext) -> list[Envelope]` and create messages only via `self.make(...)`.
- Every message goes through `MessageBus.deliver()`; Connectivity receives a `Bundle` (`messages`, `observations`, `topology`) at `POST /messages`.
- `run_incident()` in `orchestrator/run.py` is the pipeline; it must always return a schema-valid `Report`.
- `pytest -q` must stay green on `main`; `tests/test_schema_drift.py` fails if you edit models without `netcoop export-schemas`.

### Protocol `netcoop/1.0` (frozen after Milestone 1)
Envelope fields: `protocol, message_id, incident_id, in_reply_to (null only for new incident/unsolicited), sender, recipient, type, timestamp, payload`, plus `extra` for preserved unknown optional fields.
- `type` ∈ `TASK, FINDING, QUERY, RESPONSE, DECISION, ERROR`.
- FINDING payload: `finding_id, hypothesis` (`<cause>@<device_or_link_id>`), `stance` (`supports|contradicts`), `target_hypothesis, evidence_ids[], reason`, plus `consumed_message_ids[]` when built from peer findings.
- QUERY: unresolved question, target device/link, desired measurement. RESPONSE cites new evidence IDs.
- Bus validates **every** message; failures become typed ERROR messages in the trace, never silent drops. Duplicate `message_id` ignored + logged.
- Compat: 1.x accepted, unknown optional fields kept in `extra`, missing required fields rejected; 0.9 upgraded with visible record; 2.x → ERROR `SCHEMA_VERSION_UNSUPPORTED`.
- Message IDs and source IDs deterministic per fixture; findings sorted by stage, agent ID, evidence ID before scoring; wall-clock times excluded from reproducibility snapshots.

### Observations
Each canonical observation: `evidence_id, source_id, observed_at (UTC), device_id|link_id, metric, value, unit, original_field, original_value, normalization_steps[], quality_flags[]`. Missing/stale/malformed is explicit — **never converted to zero**. Links carry `capacity_mbps`.
Metrics: `latency_ms, jitter_ms, packet_loss_pct, throughput_mbps, capacity_mbps, link_utilization_pct, cpu_pct, memory_pct, queue_drops, interface_errors, link_flap_count, interface_oper_status, rssi_dbm, retry_rate_pct`, DNS/DHCP success, reachability.
Rules: derive utilization from throughput/capacity and cross-check; drops/errors are cumulative counters → per-interval deltas, negative delta = reset flag; RSSI between -75 and -67 dBm is "uncertain"; 5-min window, median/p95, ≥3 consecutive samples for sustained congestion.

### Decision
Statuses (one enum everywhere): `diagnosed, probable, healthy, insufficient_evidence, invalid_input, failed`. Only diagnosed/probable name a cause; others have `suspected_root_cause: null`; invalid_input/failed have `confidence: null`.
```
raw = clamp(0.40*signal_fit + 0.25*topology_fit + 0.20*time_fit + 0.15*independent_source_fit - 0.15*contradiction_strength, 0, 1)
confidence = round(raw * coverage, 2)
```
independent_source_fit: 1 for ≥2 distinct raw sensors, 0.5 for distinct measurement types from one sensor, else 0; agent count gives no bonus; dedupe evidence IDs.
Gates: diagnosed = conf ≥0.70, coverage ≥0.75, 2 independent sources, lead ≥0.15. probable = conf ≥0.50 with named limitation/rival. Else insufficient_evidence. healthy needs explicit normal measurements + passing service/path checks. Correlation failure after retry → orchestrator emits insufficient_evidence with `correlation_failed` limitation.

Report fields: `incident_id, status, suspected_root_cause, confidence, confidence_method, signature_version, affected_devices, affected_segments, supporting_evidence[{evidence_id,metric,value,unit,source_id}], agent_findings, alternative_causes, recommended_actions, evidence_sources, limitations, normalization_log, validation_errors, agent_trace_id`. Every cited ID must exist; every affected ID must be in topology.

### Coding rules
- Agents import only `protocol/` (+ config); never each other. Connectivity talks only over HTTP with JSON validated against `schemas/`.
- Thresholds only in `config/signatures-1.0.yaml`; record its version in every report. Never put expected outputs or labels into runtime logic.
- Never crash on bad input; return a typed ERROR / `invalid_input` report.
- Deterministic for a fixed fixture and seed.
- Type hints, small functions, a pytest test for every behaviour. After changing models, run `protocol/export.py`; CI fails if schemas drift.
- Reply with changed files (full paths) and the command to run/test them.
